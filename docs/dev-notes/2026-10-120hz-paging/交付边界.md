## 1. 目标与非目标

### 目标（唯一）
MBP 内置 120Hz 屏上左右翻页达到原生级跟手：跟手阶段 SwiftUI 零重算、位移 1:1 不丢、抬手吸附继承速度且可随时打断。

做法 = 方案 1B：**整页横向位移下沉到 AppKit/Core Animation**（AppKit 容器改 `bounds.origin`），图标/右键菜单/文件夹/页点/拖拽浮层仍是 SwiftUI。同时吸收 1A：去双层平滑、位移累加不丢、按时间算速度、吸附继承速度、高频状态隔离、只渲染相邻页、扫描移出主线程。

### 非目标（不碰，见到相关问题也不修）
- 五指捏合 / Spotlight 冲突、`SystemPinchGestureOverride`、热键、触发角、多点触控识别器
- 竖向滚动模式与搜索结果网格（`VerticalLauncherGrid`）、设置界面、新增任何用户设置项
- 图标与文件夹的视觉（阴影、glass、hover 动画、`SimpleFolderOverlay`、`folderLayer` 内部布局与动画）、图标解码/缓存策略
- 布局持久化格式（`SavedLayout`）、排序、文件夹合并规则
- 外接 60Hz 屏的帧率上限（物理限制）、打包/签名/发版/版本号/README/RELEASE_NOTES、Xcode 工程文件

## 2. 目标架构

### 2.1 视图层级与 SwiftUI/AppKit 边界

```
OverlayPanel.contentView = NSVisualEffectView                         （不变）
└ NSHostingView<LauncherRootView>  外层 SwiftUI：背景暗化/搜索框/LauncherBody（不变）
   └ PagedLauncherView（外层 SwiftUI，视口坐标）
      ├ PageStripRepresentable ─ NSViewRepresentable，frame = 整个视口 W×H
      │   └ PageStripContainerView: NSView      ← 唯一被平移的东西：setBoundsOrigin(stripX)
      │       └ StripHostingView: NSHostingView<PageStripContent>  frame = (0,0, 页数·W, H)
      │           └ PageStripContent（内层 SwiftUI，条带坐标）：点空白关闭层 + 图标 ForEach + 文件夹虚化链
      ├ 拖拽浮动图标（视口坐标，不变）
      ├ PageDotsView（只读 pager.state.targetPage）
      └ folderLayer（视口坐标，不变）
```

边界规则：
1. 每帧/每事件只发生一件事：`PageStripContainerView.setStripX(_:)`（`CATransaction.setDisableActions(true)` 内 `setBoundsOrigin`）。不碰任何 SwiftUI 状态。
2. 外层修饰符不要指望作用到 representable 上（blur/saturation/brightness/scale 对平台视图不可靠）。网格的文件夹虚化链放进 `PageStripContent` 内部；外层只给 representable 设 frame/zIndex。
3. `StripHostingView`：`acceptsFirstResponder = false`（点图标不抢走搜索框焦点）、`sizingOptions = []`、`safeAreaRegions = []`；`PageStripContent` 根视图 `.ignoresSafeArea()`。
4. `PageStripContainerView`：`isFlipped = true`、`clipsToBounds = true`、layer-backed、不绘制（`wantsUpdateLayer = true` + 空 `updateLayer`、`layerContentsRedrawPolicy = .never`）。
5. 命中路由不依赖 SwiftUI 对平台视图的 z 序：容器 `hitTest` 在 `hitTestingEnabled == false`（文件夹打开/展示中）或命中 `excludedRects` 时返回 nil。`excludedRects` 用视口坐标给出：顶部带 `(0, 0, W, topInset − 4)`（搜索框区）、底部页点带 `(0, H − 32, W, 32)`；`hitTest` 内先把父视图坐标换算成视口坐标再判断。
6. 外层原有的「点空白关闭」`Color.clear` 层移进 `PageStripContent` 最底层（条带全宽），否则被容器挡住。

`PagerMachine` 接口（签名可微调，语义不可变）：
```swift
enum ScrollPhase { case mayBegin, began, changed, ended, cancelled, other }
struct PagerMachine {
    init(tuning: PagerTuning = .init())
    mutating func configure(pageWidth: CGFloat, pageCount: Int)
    mutating func setLocked(_ locked: Bool, time: TimeInterval)
    mutating func scroll(dx: CGFloat, dy: CGFloat, phase: ScrollPhase, time: TimeInterval)
    mutating func tick(targetTime: TimeInterval)              // display link 每帧
    mutating func snap(to page: Int, velocity: CGFloat?, time: TimeInterval) // nil = 继承当前速度
    mutating func jump(to page: Int)
    var predictEnabled: Bool                                  // 仅 A/B 用
    private(set) var stripX: CGFloat        // 显示值，单一真相
    private(set) var targetPage: Int
    private(set) var restingPage: Int
    private(set) var phase: Phase           // idle / pendingAxis / tracking / ignoring / caught / snapping
    var needsFrames: Bool { get }           // pendingAxis/tracking/caught/snapping 为 true
    private(set) var gestureRawDX: CGFloat  // 本手势被采纳的原始 dx 之和（守恒校验）
}
```

### 2.3 数据流

**跟手**：`NSEvent(scrollWheel, 有 phase)` → 本地 monitor → `OverlayController.handleScroll`（文件夹打开/竖向模式时直接返回，同现状）→ `PagerController.handleScroll`：momentum 事件（`phase` 空且 `momentumPhase` 非空）丢弃 → `machine.scroll(dx: scrollingDeltaX, dy: scrollingDeltaY, phase:, time: event.timestamp)` → **同一调用栈内** `container.setStripX(machine.stripX)` → 本轮 runloop 结束 CA 提交 → 下一 vsync 上屏。display link 在跟手期也运行（preferred 120，保持 ProMotion 120Hz + 计量），但 direct 模式下不写位置。

**抬手吸附**：`ended` → `VelocityEstimator` 给出 pt/s → `PageDecision` 定目标页 → `SnapSpring(from: 当前显示值, to: 目标·W, v0)` → 每个 display link tick 用 `link.targetTimestamp` 求弹簧位置 → `setStripX` → 收敛后精确落到 `目标·W`、写 `restingPage`、停 display link。弹簧逐帧写 AppKit 几何，**不用 CAAnimation**（保证显示位置 = 模型几何，点击/拖拽/无障碍始终一致，且可无缝打断）。

**程序翻页**（页点、滚轮、拖图标到边缘、`show()` 复位）：`pager.snap(to:)` / `pager.step(by:)` / `pager.jump(to:)`，走同一弹簧与同一写入口。

**页面结构变化**（装/删 app、行列变化、拖拽时 +1 空页）：`PagedLauncherView` 在 `onAppear` / `onChange(of: size)` / `onChange(of: navigablePageCount)` 调 `pager.configure(pageWidth:pageCount:)`，同时 `updateNSView` 更新条带宽度 = `navigablePageCount · W`。machine 负责夹紧：idle → 直接跳到夹紧后的页；snapping → 改目标、保留速度；tracking → 只更新边界。

### 2.4 状态归属与高频隔离（硬规则）
- `@Observable @MainActor final class PagerState { var targetPage = 0; var restingPage = 0 }` 是 pager 唯一对 SwiftUI 可见的状态；只在值真正变化时赋值。`targetPage` 在判定/`snap`/`jump` 时写，`restingPage` 在弹簧收敛/`jump` 时写。
- `PagerController` 本身不是 `ObservableObject`/`@Observable`。stripX、速度、手势状态等每事件/每帧量**不得**被任何 SwiftUI body 读取，也不得 `@Published`。
- `PagedLauncherView.body` 求值路径里只允许读 `pager.state.restingPage`（S3 的相邻页窗口用；S2 不读任何 pager 状态）。`targetPage` 只允许在 `PageDotsView` 内、以及手势/命令回调（不在 body 内）里读。`clampedPage` 改为读 `pager.state.targetPage` 并夹紧，只供回调逻辑使用。
- 不得在 body 里调 `pager.configure`/`isLocked` 等有副作用的方法，只在 `onAppear`/`onChange` 里调。
- 锁定：`pager.isLocked = draggingID != nil || presentedFolderID != nil || model.openFolderID != nil`（`onChange` 维护）。锁定时 machine 忽略滚动手势；若锁定瞬间在跟手，弹回起始页；程序翻页（拖图标到边缘）仍可用。
- 命令语义：`step(by: n)` = `snap(to: targetPage + n, velocity: 0)`；`reset()` = `jump(to: 0)`；`stop()` = 结束当前手势/弹簧并 `jump(to: targetPage)`、停 display link。`updateNSView` 只更新条带宽度、hitTest 参数和 rootView，**不写 stripX**（页宽/页数变化一律经 `pager.configure`）。
- `PagerController` 生命周期：`OverlayController` 创建一个并持有；`makeNSView` 时 `attach(container)`，`dismantleNSView` 时 `detach`（停 display link、回 idle）。attach 时 `jump(to: 0)`（与现状一致：搜索清空回到分页时是第 1 页）。未 attach 时所有输入忽略。
- display link：`container.displayLink(target: 弱代理, selector:)`，`preferredFrameRateRange = CAFrameRateRange(minimum: 80, maximum: 120, preferred: 120)`，`machine.needsFrames` 为 false 时 invalidate。`NSEvent.timestamp` 与 `CADisplayLink` 时间同为开机单调秒，可直接相减。

### 2.5 坐标统一规则
1. 视觉位置 = AppKit 模型几何。禁止用 `layer.transform`/`sublayerTransform`/`layer.position` 动画/CAAnimation 移动网格。
2. 换算只有一个出口：`pager.viewportPoint(fromStrip:)` = `(x − stripX, y)`；`stripPoint(fromViewport:)` = `(x + stripX, y)`；`viewportRect(fromStrip:)` 同理。y 不变。
3. 内层布局用绝对条带坐标：条目中心 = 现有 `center(page:index:selectedPage: 0)`（第 p 页自然落在 p·W 起）。页切换不改任何条目的 `.position`。
4. 拖拽：内层 `DragGesture(minimumDistance: 8, coordinateSpace: .named("page-strip"))`，回调里先换成视口坐标，再调现有 `beginDrag/updateDrag/finishDrag`。`dragPoint`、`targetSlot`、`reorderSlot`、`mergeTarget`、文件夹拖出（eject）全部保持视口坐标与现有算法，`selectedPage` 取 `clampedPage`（= targetPage）。
5. 文件夹展开原点：`sourceFrame(forFolderID:)` = 该条目条带矩形（`center(..., selectedPage: 0)` ± 半格）经 `viewportRect(fromStrip:)` 换算。删除 `EntryFramePreference`、`entryFrames`、条目上的 `GeometryReader`、`onPreferenceChange`。
6. 点击/右键菜单/hover/重命名：内层 hosting 直接处理（AppKit 几何正确，无需换算）。
7. 无障碍：因规则 1，AX frame 由 AppKit 自动正确；不额外实现。

### 2.6 物理与判定参数（全部集中在 `PagerTuning`，以下为默认值）
| 参数 | 默认 | 说明 |
|---|---|---|
| 增益 | 1.0 | 不做任何平滑、死区、EMA |
| 方向 | `dx > 0` → `stripX −= dx` | 与现状方向一致（dx>0 回上一页） |
| `axisLockDistance` | 3 pt | 从 began 累加 (Σdx, Σdy)，模长 ≥3 时锁轴：\|Σdx\| ≥ \|Σdy\| 为横向，并**一次性补上 Σdx**（不丢前几帧）；否则本手势忽略 |
| `velocityWindow` | 0.05 s | 对 raw 位置做最近 50ms 样本的最小二乘斜率（pt/s）；样本 <2 或跨度 <8ms 时用最后两点 |
| `staleVelocityAfter` | 0.05 s | 抬手时距最后一次非零位移 >50ms → 速度 0（停住再抬手不翻页） |
| `distanceFlipFraction` | 0.13 | 与现状一致 |
| `flickVelocity` / `flickMinDisplacement` | 300 pt/s / 4 pt | 小距离快甩也翻 |
| `opposingVeto` | 150 pt/s | 速度反向超过此值，不按位移方向翻 |
| 阻尼上限 L | `max(96, 0.30·W)` | 与现状一致；`apply(x) = L·x/(L+x)`，`invert(r) = L·r/(L−r)` |
| 弹簧 | mass 1，stiffness 320，dampingRatio 1.0 | 解析解；越界区松手 v0 乘阻尼导数 `L²/(L+x)²` |
| 收敛 | \|x−目标\| < 0.25 pt 且 \|v\| < 2 pt/s | 收敛后精确置为 目标·W |
| predict（仅 `LAUNCHPADPRO_SWIPE_PREDICT=1`） | 外推上限 1 帧，且最近事件 ≤30ms | 只改显示值，不写回 raw；默认关闭 |

判定（d = raw − startPage·W，正 = 往下一页；v 为 raw 速度）：
```
if |d| ≥ 0.13·W && v·sign(d) > −opposingVeto      → dir = sign(d)
else if |v| ≥ flickVelocity && |d| ≥ 4 && sign(v) == sign(d) → dir = sign(v)
else                                                 → dir = 0
target = clamp(startPage + dir, 0, pageCount − 1)   // 一次手势最多翻 1 页
```

### 2.7 手势状态机（`PagerMachine`）
| 当前 | 输入 | 动作 → 下一状态 |
|---|---|---|
| snapping | mayBegin | 冻结在当前显示值（raw = 阻尼反函数）→ caught |
| idle / caught / snapping | began | startPage = (snapping/caught ? targetPage : restingPage)；raw 取当前；清空测速 → pendingAxis |
| pendingAxis | changed | 累加；满足锁轴 → 横向：补 Σdx → tracking；竖向 → ignoring |
| tracking | changed | raw −= dx；显示 = 阻尼(raw)；记测速样本 |
| tracking | ended | 计入末事件 dx；测速；判定；起弹簧 → snapping（写 targetPage） |
| pendingAxis / tracking | cancelled | 弹回 startPage，v0 = 0 → snapping |
| caught / ignoring | ended / cancelled | 若不在整页上：吸到最近页，v0 = 0 → snapping；否则 idle |
| snapping | tick | 求弹簧；收敛 → idle（写 restingPage） |
| 任意 | setLocked(true) | 跟手中则弹回 startPage；之后忽略滚动 |
| 任意 | snap(to:) | 从当前显示值起弹簧，velocity 为 nil 时继承当前速度 |
| 任意 | jump(to:) | 立即到位，target = resting = 页 → idle |
| 任意 | configure | 夹紧页号；规则见 2.3 |

## 6. 性能验收与自测

### 6.1 FrameMeter（`LAUNCHPADPRO_FRAMEMETER=1`）
每个手势会话结束输出一行到 stderr 与 `Logger(subsystem: "com.leo.launchpadprocodex", category: "framemeter")`：
```
[framemeter] #12 mode=direct track=0.62s snap=0.31s ticks=112 hz=119.6 int_p50/p95/max=8.3/8.6/9.1ms hitch=0 late_p95=0.3ms ev=78 ev_hz=125 handler_p95/max=40/90us sum_raw=-842.3 sum_applied=-842.3 lat_p50/p95=6.1/7.9ms judder_cv=0.11 body_root/paged/strip=0/0/0 pages=1→2 v=-1830 show_ms=3.2
```
- `int`：相邻 tick 的 `timestamp` 间隔；`hitch`：间隔 > 1.5×(`targetTimestamp − timestamp`)
- `late`：回调时 `CACurrentMediaTime() − link.timestamp`（主线程迟到）
- `lat`：事件写入后第一个 tick 的 `targetTimestamp − event.timestamp`（事件→上屏的近似）
- `judder_cv`：跟手期每帧显示位移的变异系数（仅参考）
- `body_*`：会话期间（began 到写 `restingPage` 之前）各 body 求值次数
