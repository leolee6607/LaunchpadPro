# 修复第 3 轮：拖拽期间回退到原版纯 SwiftUI 网格画法

## 结论（Claude 已用运行日志确认，勿再在 strip 内修动画）
图标在 PageStripView 的嵌套 NSHostingView 里。日志证明：拖拽期间邻居条目的 withAnimation(flow) 均正确触发且无后续打断，但屏幕上仍瞬移；松手后动画能播。判定：拖拽手势进行中，嵌套 host 内的 SwiftUI 动画不上屏。不要再尝试在 strip 内修让位动画。

## 方案
拖拽期间不需要翻页性能，改为：
- 拖拽开始（draggingID 从 nil 变为非 nil 的那一刻）：隐藏 PageStripRepresentable（保留其手势 owner，不要销毁、不要让当前拖拽手势中断——这是关键，见下方"手势连续性"），在外层 PagedLauncherView 的 SwiftUI 图里渲染"当前页"网格，用原版 cf82acc 的写法：ForEach 条目 + .position(...) + 原版 flow 弹簧（response 0.24, dampingFraction 0.80）做让位、落位、合并重排动画。
- 拖拽结束（落位/合并动画播完后，约 0.35s 或用动画 completion）：切回 strip 显示，外层网格移除。
- 拖拽中边缘翻页：按原版行为实现（原版用 withAnimation(spring){ currentPage = ... } 平移网格）。外层网格需要能显示相邻页并平移；切回 strip 时 PagerController 的 restingPage 与外层当前页一致。
- 文件夹内拖拽（folderDragPoint 那套）保持现状不动。

## 手势连续性（必须验证）
拖拽手势目前挂在 strip 内的条目上。切换显示时不能 remove 该视图（会取消手势）。可选做法：strip 只设 opacity 0（且 hitTesting 保持给正在进行的手势），外层网格 allowsHitTesting(false)。说明你选的做法及理由。

## 无闪烁对齐（必须满足）
- 外层网格与 strip 必须使用同一个 position(for:indexMap:) 计算、同一 cell 尺寸、同一坐标原点（strip 坐标 = viewport + pageIndex*width 的换算要一致），切换前后同一帧内每个图标像素位置一致。
- 切换在同一个事务内完成（同一次 state 更新里 strip 隐藏 + 外层网格出现），禁用该次切换的动画。
- 加单测：给定 pages/indexMap/size，外层网格位置 == strip 位置（换算到 viewport）对所有条目成立。

## 顺带修复
- 松手后被拖图标从最左侧飞回原位：原因是拖拽中被拖条目 positions 回退成 .zero。新方案下，落位动画应从松手点（dragPoint）弹到目标格，与原版一致。
- 删除 DebugTrace（PageStripView.swift 底部 enum 及所有调用）。
- 保留 PageStripStore / renderSignature（Claude 加的，用于避免 rootView 反复替换），除非与新方案冲突。

## 不得回退
- 翻页（非拖拽）性能判据不变：滑动/吸附期间 SwiftUI 重算 0。
- 被拖图标 1:1 跟手（浮层 floatingEntryView 不加动画）。
- 名字与图标一起移动，原位不残留。

## 验收
swift build -c release、swift test 通过；只改 PagedLauncherView.swift / PageStripView.swift / LauncherViews.swift 及测试；不 git commit；过程追加 施工记录-codex.md。
最终回复：手势连续性做法、对齐做法、改动文件、build/test 结果、需 Leo 实测的点。
