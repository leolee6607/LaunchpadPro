# 修复第 2 轮：拖拽重排仍有问题（上一轮"让位动画"修复无效）

截图：/Users/leo/本地/Project_Git/重要/LaunchpadPro-实验/拖拽bug截图.png（正在拖 Microsoft Excel，经过 百度网盘/Typora 附近）

## Leo 实机现象
1. App 名字没有跟着移动：被拖走的 Excel 原位置残留 "Microsoft Excel" 文字，与移入的 Typora 名字叠在一起（截图里 "Micr Typora xcel"）。
2. 让位仍是瞬间跳位，不是柔和滑开；而且距离较远的 app 也会发生位置变动（原版只有插入点之后的连续条目顺移）。

## Claude 初步怀疑（需你用代码证实或推翻）
- PageStripWindow.entries(... draggingID:) 把被拖条目仍然放进 strip 渲染；原版 cf82acc 的 placedEntries 在拖拽时如何处理被拖条目？对比后让行为与原版一致（被拖条目在网格里不应残留任何可见内容，图标和名字都不行）。
- LauncherEntryView 的 `.equatable()`（== 只比较 isDragging/isFolderTarget 等）可能吞掉了 entry 变化或 isDragging 导致的标签隐藏/图标更新，造成"图标换了、名字没换"的错配。
- 位置动画：positions 字典 + PageStripLayoutAnimation(signature:) 是否真的在同一次更新里同时改了 signature 和 positions；layoutSignature 计算是否包含 preview 顺序；验证弹簧确实在内部 hosting view 生效。
- "远处 app 也动"：PageStripWindow 只渲染相邻页、或 indexMap/activePages 在 preview 时与原版算法不同、或 reorderedPreview 的 cascadeOverflow 被重复应用。逐项对照原版。

## 要求
- 以原版 cf82acc 的拖拽重排视觉行为为准：只有受影响的条目用 flow 弹簧（response 0.24, dampingFraction 0.80）柔和滑动；被拖图标 1:1 跟手；名字与图标始终一起移动。
- 不得破坏翻页性能判据（滑动/吸附期间 SwiftUI 重算 0）。
- 为"预览重排只移动插入点与原位置之间的条目""被拖条目不在 strip 中可见""Equatable 不吞 entry 变化"加单测。
- swift build -c release、swift test 通过；只改 PageStripView.swift / PagedLauncherView.swift / LauncherViews.swift 及测试；不 git commit；过程追加 施工记录-codex.md。
最终回复：每个现象的根因（附 文件:行号）、改法、build/test 结果。

## 新增现象 3（最高优先级）：上一轮修复后左右翻页变卡了
上一轮（commit 0e79ca8，PageStripLayoutAnimation + layoutSignature）之后，Leo 感觉左右滑动比之前（772ecae）卡。
怀疑：翻页时 PageStripWindow 的可见条目随 restingPage 变化，layoutSignature 跟着变，导致整页条目触发 flow 弹簧动画或 SwiftUI 重算；或签名计算本身每帧执行。
要求：布局动画只能由"拖拽预览/提交/合并"显式触发（例如递增的 reorder token），翻页、吸附、窗口条目增减绝不能触发；FrameMeter 判据（滑动/吸附期间 strip/paged body 重算 0）必须用单测或可验证手段证明。修复后翻页手感至少回到 772ecae 水平。
